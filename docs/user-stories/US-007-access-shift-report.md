# US-007: Access Shift Report

## User Story

**As a** bartender assigned to a running shift
**I want to** access the shift's report
**So that** I can view and complete the required tasks during my shift

---

## Actors

- **Primary Actor:** Bartender (authenticated, assigned to the shift)
- **Secondary Actor:** System (Supabase Database)
- **Secondary Actor:** Task Template System

---

## Preconditions

1. User is logged in as a bartender
2. Bartender is assigned to the shift
3. The shift has status "running" (shift time has started)
4. A task template exists for generating the report

---

## Main Flow

1. Bartender views their current/running shift (via "My Shifts" or dashboard)
2. System shows a "דו״ח משמרת" (Shift Report) button for the running shift
3. Bartender clicks the "דו״ח משמרת" button
4. System checks if a report already exists for this shift:
   - If no report exists, system creates a new report from the active task template
   - If a report exists, system loads the existing report
5. System displays the report interface with all tasks from the template
6. Bartender can view tasks, their descriptions, and current completion status

---

## Alternative Flows

### AF-1: Shift Not Yet Running

1. Bartender tries to access the report before the shift's start time
2. System displays a message in Hebrew (e.g., "הדו״ח יהיה זמין כאשר המשמרת תתחיל")
3. The report button is disabled or hidden

### AF-2: Shift Already Closed

1. Bartender tries to access a report for a closed shift
2. System displays the report in read-only mode
3. Bartender can view but not edit the completed report

### AF-3: No Task Template Configured

1. System attempts to create a report but no task template exists
2. System displays an error in Hebrew (e.g., "לא הוגדרה תבנית משימות למשמרת זו")
3. Manager is notified to configure a template

---

## Postconditions

### Success
- Report is displayed with all tasks from the template
- If newly created, report record is saved in the database
- Bartender can proceed to complete tasks (US-008)

### Failure
- Report is not accessible
- Error message displayed in Hebrew
- No report record created if creation fails

---

## Data Requirements

| Field          | Type     | Required | Validation Rules                       |
|----------------|----------|----------|----------------------------------------|
| report_id      | UUID     | Yes      | Auto-generated unique identifier       |
| shift_id       | UUID     | Yes      | References the running shift           |
| template_id    | UUID     | Yes      | References the task template used      |
| created_at     | datetime | Yes      | Auto-generated timestamp               |
| created_by     | UUID     | Yes      | References the bartender who opened it |
| status         | string   | Yes      | "in_progress", "completed"             |

---

## UI/UX Notes

- Report button appears only on running shifts: "דו״ח משמרת"
- Report opens as a dialog or dedicated page
- Tasks listed with clear Hebrew labels and descriptions
- Progress indicator showing completed vs total tasks
- RTL layout throughout
- Visual distinction between incomplete and completed tasks

---

## Technical Notes

- API route: `GET /api/shifts/[id]/report` to fetch or create report
- Report generated by copying tasks from the active task template
- Each task in the report is an independent record linked to the report
- Supabase RLS ensures only assigned bartenders can access the report
- Shift status must be checked server-side before granting access

---

## Acceptance Criteria

- [ ] Bartender can access the report for a running shift they are assigned to
- [ ] Report is auto-created from the task template on first access
- [ ] Existing report is loaded if already created
- [ ] Report is not accessible before the shift starts
- [ ] Closed shift reports are displayed in read-only mode
- [ ] Report displays all tasks from the template with Hebrew labels
- [ ] Only bartenders assigned to the shift can access its report
- [ ] Error shown if no task template is configured
